# 复盘入口异常排查与修复

## 问题现象

普通复盘反馈可以正常处理，但在复盘框明确输入“直接生成新的规划”时，请求失败，随后同一会话也无法正常使用，重启服务后恢复。

出现过的错误：

- `structured_response` 为 `None`，调用 `.model_dump()` 报错。
- 接口返回“未产生复盘结果，请重试”。
- 后续请求出现工具调用与工具结果消息不配对的400错误。

## 排查结论

原调用链：

复盘接口 → 协调 Agent → 复盘或规划工具

接口要求产生复盘结果，但“生成新规划”的输入可能让协调 Agent转向规划，导致返回内容不符合接口约定。

日志确认了结构化结果为空；后续400结合重启恢复的现象，推断与未完成的工具调用状态有关。

## 修复方式

将 `POST /api/reviews` 改为通过复盘服务直接调用复盘 Agent，不再经过协调 Agent。

修改后：

复盘接口 → 复盘 Agent → 保存并返回复盘结果

由代码固定复盘入口的职责，普通聊天仍由协调 Agent处理。

## 验证重点

- 普通反馈能正常复盘。
- 输入“直接生成新的规划”后，接口仍按复盘职责处理。
- 后续同一会话无需重启即可继续使用。

## 经验

明确的页面操作可以直接调用对应服务；开放式聊天再交给协调 Agent判断，减少路由意图与接口职责冲突。
