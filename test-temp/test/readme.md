# 每日瓜分奖池分账问题修复说明

## 1. Bug 复现与原因分析

原始 `split_pool()` 函数使用以下代码计算每个人的分账金额：

```python
total = sum(weights)
return [round(pool_cents * w / total) for w in weights]
```

问题在于，每个人的金额独立使用 `round()` 取整，导致最终分配金额之和不一定等于奖池总额。

**复现案例：**

```python
pool_cents = 100
weights = [1, 1, 1]

result = split_pool(pool_cents, weights)
```

原函数输出：

```text
每人分到： [33, 33, 33]
实际总和： 99
应有总和： 100
```

三个人的理论份额均为 `100 / 3 = 33.333...` 分，经过 `round()` 后，每人获得 33 分，合计只有 99 分，比奖池少 1 分。

因此，原函数违反了“所有人的分配金额之和必须严格等于奖池总额”的业务规则。

**修复思路：**

采用最大余数法，先通过整数除法计算每个人的基础份额，再计算尚未分配的金额，按照余数从大到小的顺序，每次补发 1 分，直到分配完毕。

当余数相同时，优先分配给原列表中索引较小的用户。
